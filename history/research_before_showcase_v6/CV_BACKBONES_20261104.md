# CLIP / SigLIP2 对照、图像编码成本与预筛实验

2026-11-04。本页是 `CV_RESEARCH_20261104.md` 的固定补充实验。完整结果保存在 `artifacts/cv_backbones_20261104/`；主要脚本为 `compare_cv_backbones.py` 和 `summarize_cv_backbones.py`。

## 首先纠正模型名称

生产代码的内部别名 `siglip` 从原有实验起就指 **`google/siglip2-base-patch16-224`**，不是第一代 SigLIP。生产默认是 **SigLIP2 图像塔 + 已训练并合并的 LoRA**。历史产物目录保留原名以保护追溯关系，不把别名理解为模型代际。

本次对照包含 OpenAI CLIP B/32、真正的第一代 SigLIP B/16-224、SigLIP2 B/16-224、生产 SigLIP2-LoRA 和 DINOv2-small。第一代 SigLIP 是为澄清代际差异而补跑的控制，并非声称它是更先进的升级。CLIP B/32 与 SigLIP2 B/16 的 patch 大小、预训练数据和训练目标都不同；差值是完整 checkpoint 的任务效果差异，不能全归因于某一种 loss。

## 两种学习路线到底差在哪

| 项目 | 生产图文路线 | 本轮图像属性路线 |
|---|---|---|
| 图像输入 | 图片像素 | 图片像素 |
| 图像表示 | SigLIP2 + 图像塔 LoRA | 分别使用冻结 CLIP / SigLIP / SigLIP2 / LoRA / DINO 或经典描述子 |
| 学习目标 | 图片与可见性导向弱描述的对齐，并保留基础表示的锚定约束 | 从图像表示预测有限的可见属性 |
| 本项目监督 | 原 train3474 的馆藏字段派生弱描述；去掉年代、来源等字段，但仍不是纯像素标注 | 原 train218 的 AI 盲图属性标签；相同21属性、相同 LR 与 dev 选择规则 |
| 在线查询处理 | 原文追加规则命中的英文概念，经文本塔编码 | 固定词表解析成属性条件，不调用文本塔 |
| 最终评分 | 文本向量与图片向量的余弦 | 图片预测属性的平均 log 分数 |
| 候选图的标签、标题或描述 | 默认 image_only 不用于排名 | 不用于排名；评测真值也不参与排名 |
| 能力边界 | 自由文本，但领域术语和年代仍可能失败 | 有限属性；例如当前不能把“瓷器材质”或“万历年款”当作已支持属性 |

例如生产查询 `绿色窄口瓷器` 展开为 `绿色窄口瓷器 porcelain green narrow mouth`，保留中文原文并追加英文概念，不是完整机器翻译，也没有调用 LLM。表中的“展开英文查询”则是把事先写好的英文测试查询也经过这个相同的展开器，不是一个新模型。

属性路线把查询识别为 `green=1 AND narrow_mouth=1`，对应每张图从像素预测的分数。它确实有有限的查询规范化，但**不是把查询与馆藏现成标签字符串匹配**。训练标签教分类器看图；图库排序时使用的是分类器预测。SigLIP2 属性头也仍然继承图文预训练的视觉表示，不能称为完全不用多模态底模。

这两条路线的监督量、查询自由度和覆盖率不同，属性头高分不能解释成全面取代生产图文路线。新增 CLIP、LoRA 的相同属性头用于分离“表示质量”和“文本对齐方式”的影响。

## 协议和适用范围

沿用冻结的21意图、train218 / dev48 / test96。开发和测试遵守原 collection_v2 的 split，作品家族不跨训练/测试，LoRA 的原始训练集也没有这96张 test 图。补充实验开始时旧 test 的部分结果已经公开，因此这是事先固定方法的补充控制，不重新宣称为全新的盲测。新属性头仅用 dev 从 C=.1/1/10 选择；不按 test 选权重、阈值或候选预算。

P@5 是96图穷举标注子库中前5张的已知正例比例；未知项另保留上下界。标签来自独立 AI 图像标注及部分复标，不是真人 gold。属性头支持20/21查询，杯形训练样本不足，独立属性检索对该查询弃权计0；图文基线支持21/21。类别、颜色、形状的合取不能代表年代、材质鉴定或复杂纹样语义。

## 精确结果

数值表和计时结果由 `scripts/summarize_cv_backbones.py` 校验后保存到 `artifacts/cv_backbones_20261104/summary.json`；本页下方追加实测表。所有图文控制使用同一组中英文查询，分别保留 raw / rewritten 四种设置，见 `accuracy.json`，不能挑每种方法最好的语言当成同一条件比较。

### 图文相似度控制

| 模型 | 原始英文 P@5 | 原始英文 known nDCG@10 | 原始中文 P@5 | 展开中文 P@5 |
|---|---:|---:|---:|---:|
| CLIP B/32 | .600 | .596 | .190 | .390 |
| SigLIP B/16-224，第一代 | .724 | .762 | .590 | .714 |
| SigLIP2 B/16-224 | .752 | .762 | .495 | .610 |
| 生产 SigLIP2 + LoRA | .762 | .788 | .552 | .648 |

固定英文条件下，SigLIP2 相对 CLIP 的 P@5 点估计增加15.2个百分点，相对第一代增加2.9个百分点；nDCG几乎没有代际差异。中文在此测试集上第一代更高，说明不能把模型代际等同于所有表达下的单调提升。21个共享属性的查询、小型测试图库及未知标注都限制了外推；不能按这张 test 表重选默认模型再称为独立验证胜出。

### 同样监督、同样分类头的图像表示控制

| 图像表示 + 相同 LR 属性头 | P@5 | known nDCG@10 |
|---|---:|---:|
| CLIP B/32 | .838 | .851 |
| SigLIP，第一代 | .867 | .899 |
| SigLIP2 | .886 | .872 |
| 生产 LoRA 的图像表示 | .819 | .860 |
| DINOv2-small | .743 | .762 |
| 原图经典组合 | .648 | .631 |
| GrabCut经典组合 | .762 | .759 |

SigLIP2 的前五命中率最高，第一代 SigLIP 的 nDCG 更高；不存在所有指标统一最优的表示。LoRA 改进了图文对齐，但相同属性分类头没有优于未微调表示，不能把它描述成所有视觉任务通用增强。经典特征与 DINO 此处没有整体超过多模态预训练的视觉表示，但提供了可研究的颜色/器型信号和不依赖文本塔的控制。

### 图像→向量的实际离线成本

| 方法 | 重编码4692图总时间 | 平均每图，批量摊销 | 单图调用 P50 | 输出向量 |
|---|---:|---:|---:|---|
| CLIP B/32 | 126.4s | 26.94ms | 33.44ms | 512维，9.61MB |
| SigLIP，第一代 | 113.9s | 24.29ms | 34.82ms | 768维，14.41MB |
| SigLIP2 | 104.4s | 22.26ms | 38.70ms | 768维，14.41MB |
| SigLIP2 + 合并 LoRA | 102.5s | 21.85ms | 32.96ms | 768维，14.41MB |
| DINOv2-small，FP32 | 122.0s | 26.01ms | 32.09ms | 384维，7.21MB |

输出大小是float32 NPY字节的十进制MB，不含底模、分类头或标签。加载本地缓存模型另需约0.23–2.92s，未计入表中；首次下载成本完全独立。LoRA推理先合并权重，所以没有在每次前向另运行一条adapter网络；本轮两秒量级的总时间差不能当成LoRA加速证据。

固定256图逐阶段计时中，SigLIP2 每图摊销：解码/EXIF/RGB约7.30ms，CPU resize/归一化等processor约11.18ms，传输约.18ms，图像塔约3.94ms，归一化与回传约.05ms。生产LoRA对应约6.78/10.25/.16/3.54/.04ms。相较模型计算，当前串行读取和非fast processor占据较大比例；这些样本均值不等于全库的逐图均值。

DINO当前默认FP32，不能以表中数值声称同等精度下推理更慢。额外FP16控制仅对同256图跑3次：端到端P50为6.20s，与FP32旧向量平均余弦.999998；没有把该小样本时间外推成全库实测，也没有更改生产DINO实现。传统分支此前完整计算九套特征、8CPU进程建库243.1s，工作量和单个深度表示不同，不据此给单个HSV/HOG的速度排名。

这些离线成本发生在新建/更新图片索引时。普通文本查询复用现成向量；上传参考图才需在线编码那张新图。改变图像塔checkpoint或LoRA后必须重建相应图库向量，不能混用旧索引。

## 预筛：检索精度与删掉正确图片是两件事

预筛固定比较 raw_all、GrabCut组合、DINO属性和已由原 dev 选定的融合，之后用相同的生产 LoRA 展开英文相似度重排。保留比例预先固定为10%/25%/50%/100%，小库至少保留10张；不支持的查询全部放行。验证集要求宏平均已知正例保留率≥95%，且各查询最低≥80%，选择最小合格预算。四种方法均只能选择100%，所以没有将硬预筛上线。

只保留一半候选的 test 探索性点估计如下。保留率平均包含不支持查询的全部放行；逐查询损失和总正例损失均另保存，不能当成全4692图 Recall。

| 预筛特征 | 已知正例平均保留率 | 最差查询保留率 | 预筛后 P@5 |
|---|---:|---:|---:|
| 原图经典组合 | 87.0% | 66.7% | 77.1% |
| GrabCut经典组合 | 88.4% | 69.0% | 79.0% |
| DINO属性 | 94.3% | 67.6% | 79.0% |
| 固定DINO/经典融合 | 94.7% | 73.3% | 79.0% |
| 不预筛 | 100% | 100% | 76.2% |

前5命中率略升不等于召回保持，更不能证明删掉的全是无关图。一次查询里被排除的正确图在后续重排中无法恢复。目前适合保留为可选的软信号或预算实验，不能宣传成安全排除规则。

计时还必须看具体工作流：静态图库里 SigLIP2 / DINO 的图像编码均已离线完成，在线预筛只能减少向量点积和排序，却增加属性解析、粗排、候选复制等工作。它不能节省已付出的建库成本。如果未来后续阶段需要对候选运行昂贵的局部匹配或新图像推理，预筛可能有实际价值，需要对那个阶段另测收益与漏检预算。

4,692候选的随机交错计时中，共用的查询文本向量已预先编码：直接余弦+排序P50 **1.56ms**；经典/DINO预筛保留50%后相同余弦重排约**3.95–4.11ms**，融合约**6.28ms**。只保留10%时经典/DINO约**1.75–1.79ms**，仍未超过不预筛。这里已包含预筛解析、评分、排序和候选数组复制；未包含HTTP和共用文本塔。当前图库规模和实现下，没有获得加速，不能用“比较的向量少了”代替实际耗时结果。

## 图到图路线的解释边界

本页 DINO/经典预筛使用**学习的可见属性分数**，不是把文本直接塞入 DINO，也不是同物的关键点匹配。已经实现的“专业文本→外部参考图→DINO/SigLIP2图图相似度”是另一条完整路线，参见 `REFERENCE_RETRIEVAL_RESULTS.md`。旧8意图实验里多参考DINO P@5=.600，多参考SigLIP均值=.675，融合=.750；这组数据与本页不同，不能拼成同一排行榜。DINO在梅瓶/葫芦等具体器型上有效，但没有总体胜出的证据。

同样，HOG、HSV、LBP、Hu/轮廓是本轮的经典特征；本轮没有新增 SIFT/ORB 几何匹配测试。相同物体/近重复匹配与跨器物的“龙纹”等语义识别需要不同的标注和实验，不能混为一种已验证能力。

## 复现与产物

```powershell
# 先恢复原v2图库、三套底模、生产LoRA与旧研究特征/标签。
python scripts/compare_cv_backbones.py all
# 原始SigLIP checkpoint须单独下载并固定revision；主脚本默认离线加载。
python -c "from huggingface_hub import snapshot_download; snapshot_download('google/siglip-base-patch16-224', revision='7fd15f0689c79d79e38b1c2e2e2370a7bf2761ed', allow_patterns=['*.json','*.safetensors','*.model','*.txt'])"
python scripts/compare_cv_backbones.py siglip1
python scripts/compare_cv_backbones.py latency
python scripts/summarize_cv_backbones.py
```

已存在的属性头选择拒绝覆盖；新的研究应使用新的输出目录。计时在本机 RTX3070 8GB 上进行，batch16，Torch2.9.1+cu128 / Transformers4.57.6；CLIP/SigLIP采用FP16 autocast，DINO生产实现为FP32，另保存DINO FP16小样本控制。所有GPU阶段边界同步。全库计时实际重新编码4692图，不按小样本外推；不含模型下载、模型加载与向量文件保存。逐阶段计时使用固定哈希抽样256图，单图延迟32次暖机后调用。文件缓存与功耗状态没有严格控制，因此不将一次顺序全库运行差值当成模型固有速度提升。

`encoding.json`保留解码、processor、CPU→GPU、图像塔、归一化和回传的每批原始观测。`prefilter_latency_interleaved.json`将各方法随机交错测量，避免将顺序运行时的缓存/时钟差异误读为预筛加速；初始顺序计时仍保留在`prefilters.json`，以交错结果为主。

`acceptance.json`核对冻结协议、原LoRA训练隔离、三组属性头全4692预测重算、五种实际重编码向量归一化/旧索引一致性、预筛弃权放行和不预筛排序一致性。`artifact_manifest.json`记录产物与脚本哈希。原始模型卡和官方代码说明快照在`literature/`，用于确认模型身份，不替代本地效果证据。新checkpoint、研究向量和结果没有被冒记进此前的资源Release。
