# 以图像为主轴的技术路线

更新：2026-10-30。用户补充强调：主要研究对象是计算机视觉检索，而不是对馆藏描述做文本搜索。以下路线替代“混合检索分数就是主要效果”的理解。

## 分层任务与可检验目标

1. **大类**：用冻结 CLIP、SigLIP2 的图像向量与文本向量检索；在图像向量上训练材质/器型分类头。馆藏字段可作为训练弱标签，但在线 `image_only` 排序不读取描述、BM25 或元数据槽位匹配分数。
2. **可见细节**：从严格分离的 train/dev/test 图像中生成无标题盲卡，由 AI 看图标注器形、器物本体颜色、口颈/把手/足等形状、清楚可见的纹饰及简短视觉 caption。unknown 保留为空，不把“看不清”当负标签。在 SigLIP2 图像特征上训练多标签 sigmoid 头，并尝试以图像描述进行 LoRA。固定 test 后比较 zero-shot、metadata-caption LoRA、visual-caption LoRA、图像属性重排。
3. **专业描述**：将“青花、粉彩、窄口”等可解释外观词展开为普通语言；“清乾隆”等年代来源只作用户明确选择的馆藏筛选。不能仅凭颜色形状证明朝代、真伪、工艺或专名身份。系统应展示哪些部分参与图像匹配、哪些仍未核验。

预期是 SigLIP2 能处理基本器型与明显颜色，独立训练头可能改善颜色/形状的组合查询；细纹饰、材质相近外观与小样本类别仍困难。这些是待验证假设，不能预填收益。

当前采用共享图像特征的软重排，不先用预测大类作硬筛选。例如“绿色、窄口瓷器”同时使用图文语义、材质头和支持数足够的颜色/器形头；任何一个头的误判不会直接删除候选。用户手动选择的馆藏facet才是硬条件。这样避免先筛“瓷器”时的一次分类错误让正确图像永远无法召回，也保留未知属性。不同属性用相同SigLIP特征，但不是把所有细节当作一个互斥类别。

训练规模与预期能力分开：器型/材质利用3,474条训练图像的馆藏弱标签；视觉细节和外观caption只用218张有效AI训练图，因此只训练满足正负支持数的轻量头，并以LoRA限制可训练参数。不会承诺完整专业术语识别率。正式目标是独立test上的检索指标与区间、逐属性支持度/F1/AUC以及实际延迟；若某种训练或细节重排没有改善，保留负结果，部署仍按dev选择。

## 对照与选择

- `baseline`：原文图文稠密检索。
- `translated`：规则跨语言展开后，纯图文检索。
- `image_only`：图文相似度加图像分类概率；不使用馆藏文本排序。材质器型头的弱标签来源与独立视觉细节头的来源分别披露。
- `hybrid` / `visual`：另列为元数据辅助对照，不拿其银标优势证明视觉识别能力。
- 显式 UI 筛选是用户约束，必须在界面说明来自馆藏字段；自由查询图像评测不使用这些筛选。

所有 epoch、分类器正则化与重排权重只按 dev 选择；test 不用于调参。自由视觉查询从像素编写，并穷举指定盲图库所有图像的相关性。AI 图像审计不等于真人 gold，不报告虚假的双标或一致性。

## 预处理与可复现性

保留原图、长宽比缩放图和缩略图，分别记录 SHA256；模型使用官方原生 processor。先不对全图库强制裁切器物或放大纹样，以免移除口颈、足或纹饰。需要局部细节的失败样例单独分析；是否增加分割/多裁剪以 dev 的真实收益和耗时为依据。

在线 LLM 或联网搜图需要额外 API、延迟、来源与许可管理；本阶段先完成可离线复现的视觉主干和可控专业词展开。未取得有效 API 凭据时不假装接入外部 LLM。该扩展可作为后续实验接口，而不能替代本机模型的验证。
