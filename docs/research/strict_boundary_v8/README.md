# 严格逐项筛选 · 2026-11-16

后续用户验收发现通用查询与双语、灰度颜色错误，本版未达到产品要求。见 [失败复现与替代方案](../boundary_redesign_v9/PROPOSAL_ZH.md)。以下为 v8 当时的实现与历史验证记录。

用户选择“严格筛选：优先准确，允许漏掉一些”后，集合检索默认改为 `strict_conditions`。这版解决原来总分可以补偿缺失条件的问题：器型、颜色、窄口等显式条件必须分别通过检查；未能确认的候选放入待核验，不计入 Yes。当前是本地工程版本，未提交或推送 GitHub。

## 使用

运行 `bash scripts/run_local.sh`，打开 `http://127.0.0.1:8000/`，选择“筛选匹配集合”。检索设置默认为“严格逐项筛选”；“综合条件分数（宽松）”保留 v7 对照。

`POST /api/search/set` 省略 `method` 即使用严格模式：

```json
{"query":"绿色窄口瓷瓶","top_k":24}
```

`results` / `matched_item_ids` 只包含 Yes；`uncertain_results` 单独返回待核验候选，`yes=null`；`top_k` 仅截断 `preview`。两组均完整返回并可分页，每张待核验卡片显示未能确认的条件。`matched_count + uncertain_count + rejected_count = gallery_count`。`rejected_count` 指未入选，不代表每张图都已证明不相关。

## 算法与明确边界

1. v7 模型先给全库 4,692 张图片计算分数，产生候选集。这一步也可能漏检；后续严格验证不会召回池外图片。
2. 将查询解析为显式条件，对每项条件分别比较正向提示词与反例提示词。器型反例增加罐、壶、杯、雕塑、碎片等；颜色反例包含粉、棕、灰等相近色，并区分有色主体与白/灰底彩绘。对照差值至少 0.01 才获得文本视觉支持，低于 -0.01 视为检查不通过，中间区间待核验。
3. 颜色使用图像边缘背景估计得到器物前景，检查分割质量，补足轮廓内的小块遗漏，避免只统计彩色纹饰。普通颜色查询要求目标颜色占前景内部至少 50%，且为最大颜色份额；不足 25% 不通过，25%–50% 待核验。灰度照片、无效分割、过多补全均不能凭颜色直接入选。蓝白纹饰使用独立组合条件，不等同于蓝色主体。
4. 窄口使用居中、直立轮廓的上部宽度与器身宽度之比作为保守代理。上部 2%–18% 最大宽度不超过器身 20%–90% 最大宽度的 45%，并且窄口图文对照通过，才可入选。明确的上缘 2%–6% 宽度达到器身的 60% 则不通过。上部较宽但上缘较小的短颈瓶进入待核验，避免把瓶肩当作口沿。
5. 所有条件取 AND：任一检查不通过则不入选；无不通过项但存在 unknown 则待核验；只有全部 supported 才能 Yes。未支持的否定、专业器型、年代、工艺等不能由原句高分直接变成 Yes。

轮廓比例是二维图像代理，不是测量出的真实口径；斜拍、遮挡、瓶盖、复杂背景、低饱和色和短颈器型仍会造成误判或弃权。以上阈值是明确披露的工程规则，没有经过独立窄口/颜色标注校准，不具有准确率保证。`score` 仍是 v7 排序支持分数，不是正确概率。候选标题、材质与年代元数据不进入决策。

实现：`src/curio/retrieve/strict_boundary.py`，版本 `strict-pixel-and-v4`。前景特征缓存按版本、路径、文件大小和修改时间失效；仅在候选图片上计算像素特征。

## 已有测试核心回放：准确优先的代价

| 语言 / 方法 | 微 Precision | 微 Recall | 宏 F1 |
|---|---:|---:|---:|
| EN / v7 综合条件分数 | 0.6130 | 0.7857 | 0.6604 |
| EN / 严格版 | 0.7030 | 0.5635 | 0.3972 |
| ZH / v7 综合条件分数 | 0.6629 | 0.7024 | 0.5536 |
| ZH / 严格版 | 0.7927 | 0.5159 | 0.3614 |

口径：全库决策，仅在原有 140 张 test 核心、20 个中英共享意图上计分；grade=3 为正，0/1/2 为负，-1 排除；待核验不算接受，因此其中正例计为漏检。严格版 EN 为 TP142/FP60/FN110，ZH 为 TP130/FP34/FN122。年代、圆腹、敞口等未确认条件会产生空集合，宏 F1 明显下降。

这是已被反复检查的数据上的回放，不是独立新查询测试，更不是全库准确率。不能宣传“全面优于 v7”或“解决所有窄口误收”。此轮没有训练新的属性检测器，也没有完成新的人工标注。后续独立标注材料见 [v7 FOLLOWUP](../set_boundary_v7/FOLLOWUP.md)；要得到可承诺的边界，还需要对口沿定位、主体色和困难负例单独标注、校准并冻结验证集。
