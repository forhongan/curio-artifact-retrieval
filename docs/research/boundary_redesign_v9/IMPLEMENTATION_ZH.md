# 图文联合判别 v9：本地实现与实测

本轮把 [设计方案](PROPOSAL_ZH.md) 落成了可运行的实验路径。它不是已经通过准确率验收的默认算法，也没有把模型分数称为正确概率。

## 已实现的判别流程

1. 中文/英文已知同义词映射为同一个概念定义、问题、缓存键和边界。梅瓶、葫芦瓶不再因旧解析器“不支持专业器型”而一律进入待核验。自由词语与否定句进入语义转换，保留未知约束；语义转换失败会报错。
2. `Qwen3-VL-8B-Instruct` 的 MLX 4-bit 版本同时读取图片与完整查询，取得首 token 的 Yes/No 对数分数。固定版本、448 像素预处理；单独的 `.venv-vlm` 不升级原有检索环境。当前提供 Apple Silicon 后端，未实现 CUDA 后端。
3. 全部颜色条件先检查照片颜色是否可观察，包括白色、黑色、青花。纯灰度照片不参与颜色入选，但仍可判断形状。此检查不能证明任意有色背景中的主体颜色均可观察。
4. 专业器型可通过显式参数试验正负参考图片，现默认关闭；通用查询的参考适配由拟合分组中的正例与高分反例构成，因成绩下降未获准用于在线判断。候选图不发送藏品标题、年代等目录字段；同器物、重复图片与参考图隔离。
5. 单独训练 Yes/No 分数的逻辑回归校准头，并在不同器物的校准集选择阈值。**没有微调 8B 模型的权重或训练 LoRA**。参考版校准参数绑定模型、确切查询和参考库哈希，不向未见概念套用。未达验收目标的产物保持实验状态。
6. 新 API 异步扫描完整图库；只有全部图片完成，才返回完整集合。每图输出布尔 `yes` 及原因；不再产生几百项“待核验”。No 表示这张照片未被本次筛选接受，包括不符及证据不足，不等于证明实物没有某个属性。
7. 任务支持进度、取消、重试与逐图缓存。模型进程错误、超时、无效分数不会被转换成一次成功的全库 No。进程随服务关闭释放。

## 复现入口

```bash
bash scripts/setup_joint_vlm.sh
pnpm --dir web build
bash scripts/run_local.sh
```

打开 `http://127.0.0.1:8000/`，选择“筛选匹配集合”→“检索设置”→“看图联合判别（实验版）”。旧严格规则仍是默认对照。

```bash
# 原始 VQA、拟合/校准头及历史方法对照
PYTHONPATH=src .venv/bin/python scripts/run_joint_vlm_v9.py
# 只用拟合组选择正例和困难负例
PYTHONPATH=src .venv/bin/python scripts/run_joint_reference_v9.py
# 用原始 VQA 与冻结的对比特征拟合融合头，仅离线研究
PYTHONPATH=src .venv/bin/python scripts/run_joint_fusion_v9.py
# 在相同 8 类和 140 张测试图上比较 v7、v8、v9
PYTHONPATH=src .venv/bin/python scripts/summarize_joint_v9.py
# 专业器型、灰度问题与新词语的探索案例
PYTHONPATH=src .venv/bin/python scripts/verify_joint_specialty.py
# 全库 HTTP 与中英文缓存一致性
PYTHONPATH=src .venv/bin/python scripts/verify_joint_api.py
```

新接口：`POST /api/search/set/jobs`（`query`、`use_references`，后者默认 false），`GET /api/search/set/jobs/{job_id}`，以及 `POST /api/search/set/jobs/{job_id}/cancel`。完成后添加 `?decisions=true` 可取得所有图片的 Yes/No 与原因。历史同步 `/api/search/set` 保留原方法，避免把后台计算未完成误报为零结果。

## 评测边界

首轮固定 8 类意图：瓷器、瓶、碗、蓝白纹饰陶瓷、绿色瓶、红色瓶、龙纹、莲纹。200 个历史核心图像形成 1,600 个图文对；原 dev 按器物组分为拟合/校准，140 张 test 不参与拟合或参考选择。中英文翻译不是两倍独立测试样本。

标签来自此前 AI 看图与馆藏资料核查，**不是独立人工金标准**。第二轮参考实验还属于看过第一轮测试结果之后的适配比较，因此只能报告探索结果。原标签中的未知项不进入 Precision/Recall 的分母，另计误入未知数量。

同一固定测试集上的数量比全库数量更可比，但依然不能宣称“全库准确率”。全库 API 验证只证明覆盖、输出契约、双语一致性与运行成本，不自动提供 4,692 张图片的相关性真值。


## 实际结果与部署决定

同一 8 类、140 张历史测试图、1,120 个图文对的微指标如下。未知标签不计入相关性指标；这些是历史 AI/资料核查标签上的探索比较。

| 方法 | Precision | Recall |
|---|---:|---:|
| v8 严格规则，中文 | 75.0% | 58.4% |
| v8 严格规则，英文 | 68.6% | 63.7% |
| 原始 VQA，阈值 0.5 | 68.7% | 81.4% |
| VQA + 分数校准头 | 72.9% | 69.0% |
| 正反参考 VQA + 校准头 | 69.5% | 58.4% |
| VQA + SigLIP 对比特征融合头 | 80.6% | 69.9% |

融合头在原始 VQA logit 与 9 个既有对比特征上拟合，正则参数预先固定为 C=0.1，未做测试集超参搜索。它是在看过前序结果之后提出的适配实验，仍需全新人工测试。其校准集 Precision 为 75.9%、Recall 为 71.0%，没有阈值同时达到预定 90% Precision、50% Recall、至少 5 个 TP 的条件。

**没有任何新方案通过预设验收。** 保留旧默认；网页的“看图联合判别”是原始 VQA/适用概念上的一维校准实验路径，**80.6% 的融合头仍是离线研究，不是网页当前算法成绩**。正反参考默认关闭；参考库校准产物同时要求 `release_approved` 与 `calibration_goal_met` 才能被服务加载，目前均不满足。研究文件存在不等于自动部署。

专业器型的 20 个探索案例：无参考版本答对 14 项，带参考版本 13 项。梅瓶正例 4 张仅认出 2 张，带参考则全漏；葫芦瓶正例 4 张都认出，但无参考也把 4 张相似非葫芦瓶都误收。四张此前误入白色查询的纯灰度图均被拒绝。**这组结果明确说明梅瓶/葫芦瓶的可靠边界仍未解决**，不能用本轮代码接通代替质量验收。

另发现一部分旧标签混入目录功能分类：例如 `met_52078` 的旧记录明确写“bowl-shaped but official small cup retained”，在碗查询中被计为负例。另一些是真错误，如盘、残片被当碗。旧分数保持不改；后续人工标签需要统一“可见外形”与“目录分类”的判定口径。

## 全库实测与页面验证

“青花瓷” / “blue and white porcelain” 完成全部 **4,692** 图：**411 Yes、4,281 No、0 待核验**。中英文返回同一任务与完全相同的入选 ID；不是两个数量恰好相同的集合。此查询不在当前校准头的确切概念范围内，因此使用原始 VQA 0.5，API 如实标记 `calibration_applied=false`。

No 中有 1,063 张因照片颜色不可观察而排除。重查全部 411 张入选图，没有低于同一颜色可观察性门槛的图片。这只验证灰度门槛，不证明所有入选图的器物颜色或青花类别正确。确定性抽取的 30 张入选图中，AI 看图发现一张明显多彩器仍被收进来，以及三张类别/颜色证据模糊的图；没有据此调整阈值，也不把抽查当独立人工准确率。

首次任务墙钟时长约 **154.6 分钟**，包含与参考实验共享资源及本机运行状态影响，不能冒充纯推理吞吐；这已经证明首次全库扫描的交互成本很高。相同查询/同义词可复用完整缓存。取消、进度、完整分页、中英文缓存命中、手机布局与无浏览器脚本错误均做了真实检查。

专业名词转换也做了修正：新增有博物馆依据的玉琮与抱月瓶定义，翻译进程只翻译原句，不自行扩写器型知识。玉琮依据 [Met 的器型说明](https://www.metmuseum.org/art/collection/search/72376)，抱月瓶依据 [British Museum 的陶瓷展厅说明](https://www.britishmuseum.org/sites/default/files/2021-05/large_print_guide_room_95_chinese_ceramics.pdf)。同义词共用定义；“红色没有把手的罐子”与英文原句实际转换为同一问题，保留红色与否定条件。任意未见专业名词的正确性仍不作保证。

## 独立复核入口

`http://127.0.0.1:8000/#boundary-review` 提供 720 个冻结的新图文对。沿用此前按器物组分离的 40 张 dev、80 张 test 与 12 个新组合意图，不按新模型得分挑样。页面隐藏预测、分数和藏品名称，允许“是 / 否 / 无法判断”并记录依据；记录只保存在当前浏览器，填写复核者后可导出 JSON。

生成命令：`PYTHONPATH=src .venv/bin/python scripts/prepare_joint_review.py`。输出仅为未标注队列，不会填充或覆盖人工标签。导出文件标记 `manual_review_export_unverified`；必须核对复核者、样本划分与标签后再进入训练，不能因文件存在就当成人工验证已完成。浏览器验收用的合成记录留在 `artifacts/joint_vlm_v9/ui/review-ui-test.json`，不可用于训练或计分。
