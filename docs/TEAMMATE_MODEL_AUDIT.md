# 组员模型与扩大图库核验

检视仓库 `zhizhizhi-victor/curio-artifact-retrieval` 的本地源码 HEAD 为 `c852155feedc7a923148f99d33fb2f7f357c0946`。只下载已训练模型／向量和记录包，没有下载完整图片库；两个 ZIP 都通过发布清单 SHA256 校验。文件位于 `research/teammate_review/`。

## 实际训练和数据

新检查点为同一 SigLIP2 固定 revision 上的 rank 12、alpha 24 LoRA，共 995,328 个参数。除图像注意力 q/k/v/out 外，更新空间池化头的 attention.out_proj 和 MLP fc1/fc2；采用双语描述、属性反事实负例，以及 218 张细粒度描述补充。训练仍使用原 train 的 3,474 张图片，开发集 568 张。不能说是在 10,200 张图片上训练的模型。

扩大图库确有 10,200 件：Met 3,904、MIA 2,955、Cleveland 1,810、AIC 1,531。没有发现故宫来源。新图片的 split 是检索扩展用途，不应直接当成独立带真值测试集。

## 公平对照

原始查询对照使用相同 4,692 个候选和同一 v5.1 判断。另用隔离 Python 进程直接运行组员未修改的 `SearchService`，在两个检查点上分别测试 `image_only`、`subquery_and`、`compositional`，并在 4,692 与 10,200 两个图库运行；两检查点都用匹配的视觉探针、相同 .15 权重。生产正式配置的探针权重仍为 0，此处是控制实验，不代表修改了生产选择。

结果位于 `artifacts/relevance_v5/team_workflow/results.json`。重写通常比原始中文输入好，但新检查点在本核心未超过现有生产检查点；组合算法也不是所有查询都更好。扩大图库会改变探针／分数的相对归一化，核心排序变化本身不能证明新增图库质量更好。

额外取四类查询、两个模型在 10,200 图库的实际前五，形成 25 张不同图片的结果池。18 张实际可查看，7 张 AIC 请求被 403 拒绝，Chrome 打开馆藏页也停在安全验证；未作视觉判分。这些未知项保留为精度上下界，不当作错误或正确。实际看到了青花查询表现较好、明代查询混入元／清代、乾隆查询混入元／宋代以及玉器。读图记录与图片在 `artifacts/relevance_v5/large_gallery_review/`。这是四意图观察，不是 10,200 图库完整准确率。

## 组员评测是否更好

其双语复杂查询、解析器复合词保护和反事实负例值得保留为研究对照；数据规模扩大也有实际价值。但其视觉 test 仍继承旧 60 图 AI 相关性，并没有提供更可靠的独立人工标注。

`src/curio/evaluate/benchmark.py::grade` 明确将“器型、材质满足，而必需纹样或年代不符”给 grade 2；使用 grade ≥ 2 的二值指标就仍把这类图计作相关。这适用于宽松 silver relevance，不能证明复杂条件全满足。报告已披露 silver 性质，本次也不把其不同定义的高分直接否定或当作本系统进步。

还发现一个实际数据问题：MIA `1000` 的原始记录是 `480–221 BCE`，其标准化快照却为正数 `[221, 480]`。记录包中的原始 JSON 已单独提取，保留在 `resources/data/raw/mia/1000.json`；年代评测不能直接信任这类解析字段。没有修改组员原仓库。

因此采用统一修订核心，而不是更换成组员的评测标签。主结果只在已核查范围内成立，不以单一表格宣布某检查点在所有文物或所有查询上优越。
