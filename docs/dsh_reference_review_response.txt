## 1. 最严重的实际弱点

**结构性问题**：**一个意图只对应一组参考向量，并且共用一套全局聚合规则**。这条路线里，参考选择是单点故障，聚合又把错误藏了起来，导致无法归因。

用你自己的数字看出三点：

- **聚合方式的有效方向在不同意图之间来回翻转**：mean 在 blue-white 上是 0、在 gourd 上是 .8、在 meiping 上是 .8；max 在 meiping 上是 1、在 gourd 上是 .2。如果参考集本身成分干净，mean 和 max 不会互相打脸。**blue-white 的 mean=0 与 single=1 同时成立，说明参考集里混了不同器形、不同来源摄影的图**——平均先把“形态”信号抵消掉，白底差异再把呈色稀释掉。所以“多参考不如单参考”是错误归因，真实原因是参考集没有按属性分组。
- **specialist 的 P@5 首先反映的是覆盖率，而不是判别力**：888/4692 = 18.9%，其余 81% 的图像根本没有特征，不可能进入 top5，于是“不投票=零分”。shape .00 是覆盖率 bug 的报告，不是“形态无用”的结论。同理，color-only .05 也很可能是白底主导 HSV 直方图的结果（馆藏照片大面积是背景），而不是颜色无用。
- **参考库自身没去重**：你把参考与画廊做了 ID/accession 家族/SHA/aHash-pHash 排除（这一步很扎实），但没做参考之间的近重复。同一器物的三张不同角度照片会让 mean 给这一个视角记三份权重，直接加剧上面的抵消。

两个几乎零成本、且属于“真正的视觉改进”的修正（不需要新模型）：

1. **按属性拆参考集**：形态参考（同器形族、正/侧视清晰）、呈色参考（同釉色/同工艺）、纹样参考分开，**在分数级融合**，不再把不同属性的参考向量平均成一个。聚合器换成 **medoid / trimmed mean**（按参考两两相似度的中位数裁掉离群参考），规则预先固定、对所有意图一致应用，不在 8 意图池上挑。
2. **颜色特征改成物体加权**：HSV 直方图按“像素与边框背景色的距离”加权，再加一个中心先验，替代全局直方图。这是 color-only .05 和 blue-white mean=0 的同一条根因。

顺手还有一个一致性问题：**排序用 RRF，UI 却展示 cosine gap**。用户看到的“差距”并不是产生这个排序的量，会出现“分数变了但顺序没动”；要么把秩融合换成 z-score 加权和（能保留 cosine 差距），要么 UI 改报秩差。

另外，每个意图 ~5 张参考对抗不了噪声。Met/Cleveland 的 CC0 池很大，把每个意图扩到 20–30 张、按器形/呈色分层，是这条路线里性价比最高的一步——它改变的是真实视觉检索质量，不是评测。

## 2. 下一个值得测的算法（形态）

**无训练的“列剖面 + patch 对应”形态描述子**，替代现在的轮廓剖面：

- 取 SigLIP2 最后一层 patch token（224 → 16×16，14px/patch）。背景锚 `b` = 图像四条边 token 的均值（馆藏摄影背景近似常量，不需要分割）。
- 每列能量 `e_j = 1 − cos(col_j, b)`，归一化得到剖面 `p`；用 `e > τ`（τ 固定、不调）取纵向 extent，重采样到固定 24 点 → 尺度/平移不变的形状签名。
- 匹配用对称 Chamfer 与 DTW 取较小值；**只用于 top-100 内部重排**，或与 SigLIP 分数 z-score 后固定 0.25 相加，不在意图池上调权重。
- 为什么能绕开当前失败点：**不依赖启发式分割（覆盖 100%，彻底避开 888 那道坎）**；不用二值轮廓，只用列能量，白底在两张图上同时趋零、天然抵消；保留了“肩—腹—足”的纵向位置，这正是梅瓶/葫芦/玉壶春的分界，而 1 维轮廓剖面丢掉的恰恰是它。
- **不用 8 意图池来评估**：用馆藏标题/object name 中的形态词（meiping/梅瓶、gourd/葫芦、baluster、玉壶春…）做弱标签，在 FULL4692 上做 type-level 检索，报 mAP 与 Recall@20。排序链路仍然只吃像素，标题只用于打分——这不是加标注，是把已有元数据当弱标签，属于真实的视觉实验。**先冻结这个指标集，再动手实现。**
- 一个必须排除的混淆：如果 image LoRA 训练时见过含这些形态词的 caption，就要额外报一个“无 caption 监督”的 ablation，否则无法区分是视觉学到的还是语义泄漏。

纹样留到后面：224 下 14px/patch 对龙纹、缠枝太粗，局部语义纹样需要 448 输入或 ROI 裁剪，先解决分辨率再谈 DINOv2 局部匹配。

## 3. 仍然过度的声称

- **EN .975 / ZH .775 的对比**：单一 AI judge、且四个意图由 root AI 评、另四个由独立 agent 评。如果 EN 与 ZH 不是同一 judge 覆盖面，语言差距里混着 judge 效应。这只能叫“AI 判定的相关性代理”，不能叫语言效应。
- **把 specialist 的 P@5 与 text P@5 并排放**：19% 覆盖率 + abstain=0 vs 100% 覆盖率，两者不可比；应在每个 specialist 列旁标“有效画廊 888”，否则读者必然得出“形态无用”的错误结论。
- **fusion .75 > 单参考 .625**：8 个意图、P@5 步长 0.2，.05 的差 = 1.5 个 grade2 命中。既然声明了不做显著性，就不要让它在表里以“赢”的姿态出现；报 **per-intent 胜/平/负计数**比均值诚实得多，8 个意图本来就撑不起均值。
- **“text-to-external-reference”这个名字**：现在它等价于“8 个预声明意图 + 人工挑选参考”。对任意 query，规则规划器选出不合格参考时并没有“参考不合格就拒答/退文本”的纯度判据，泛化性没被覆盖，但 UI 面向任意 query。
- **“official reference bank”**：CC0 与官方来源是事实；“trusted”不是——参考图的背景/打光差异本身就是 blue-white 失败的主因。
- **opt-in 4793**：101 张下载图的拍摄规范未知，任何在 4793 上引用的数字都是另一个分布，不能与 4692 上的历史数字并列。

## 4. 交付判断

**合理**，但需要四个条件，缺一条负面结果就会变成不诚实的判决：

1. 措辞从“没有帮助”改成“**在本架构下未被证明有帮助**”，并列出三个混淆项（覆盖率 19%、固定 .75/.25 融合权重、参考集污染）。否则负面结果会被读成给未来工作判死刑。
2. 默认不变 + opt-in 明确标 uncalibrated + 新 101 图不进入任何已发布数字。这三点你已经在做，保持。
3. “剩余研究”要具体到可验收：学习式分割/局部语义纹样匹配、可选真实 LLM 规划。但要写清：**LLM 规划修不了像素问题**，而且它会因为“挑到更匹配的参考”制造虚假增益（表面变好、归因错位），建议只做离线对比、不进默认路径——它也和你现在 274 个测试的确定性相冲突。
4. **shape .00 以“覆盖率 bug”入档，不以“形态无用”入档**。这是最有信息量的负面结果，压平了就浪费了。

一句话：最该先做的视觉改动是**参考集按属性拆分 + 物体加权呈色 + medoid 聚合**（改的是排序质量，不是评测），然后把列剖面形态描述子放在独立弱标签集上验证；两者都不需要碰这 8 个意图池。
