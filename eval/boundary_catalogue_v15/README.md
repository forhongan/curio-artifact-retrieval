# 馆藏类别与图像联合边界 · v15

用户已授权线上使用馆藏类别与图像共同判定，记录见 `authorization.json`。本路径允许标题、器类和材质字段提供器物身份；颜色、口部及显式外观条件仍须照片支持。历史 v9–v14 纯视觉成绩、标注与模型不作回写。

## 判定方法

1. 中英文已知概念编译到同一条件集合。梅瓶、青花瓷、红色碗和绿色窄口瓷瓶保留全部条件；葫芦瓶泛称、双腹、三节分别编译。未识别的修饰语和否定不能直接丢弃，而是交给原完整查询规划及看图判别。
2. 馆藏器类以 `object_name` 优先，其次读取标题的主语部分；不从描述中的装饰题材推断主体。明确的杯与碗、罐与瓶等冲突会排除。明确的梅瓶、葫芦瓶名称及材质可提供正证据，但标题里的“红”等词不能证明照片颜色。
3. 命名器类仍检查照片主体是否一致；葫芦瓶另检查照片中的腹部形态，避免所有含 Gourd 的标题无条件通过。没有明确器类记录时回退到逐条件视觉问题。梅瓶的馆藏身份允许历史器形变体；额外查询“窄口”时仍检查可见口部。
4. 窄口采用照片轮廓的严格工程条件：口缘与器身宽度比 ≤ 35%，同时须通过可见开口与非宽口/遮挡检查。比例来自主体分割的顶部口缘与中下部最大宽度，是照片近似量；尚未经过独立人工测量校准。分割无效时不能据此放行。
5. 有颜色条件时，先拒绝黑白或颜色不可观察的照片。红色使用既有主体区域颜色分类器加正反视觉证据，青花使用冻结的分项视觉模型，并要求直接正向证据肯定、反例证据否定；其他常用色要求主体区域至少一半满足指定 HSV 范围，并获得视觉语义支持。该面积标准是工程规则，尚无独立校准成绩。
6. 每个必要条件必须通过。对外返回完整 Yes/No 集合，No 包括明确不符和证据不足；模型错误、超时与文件错误会使任务失败，不能伪装成完整的全 No 结果。逐件结果保存馆藏字段或图像证据来源。

这是逐条件保留依据的混合判定流程。对任意自然语言的准确率仍需独立评测。

这些修正来自已见案例；本轮结论属于开发与回归诊断。不能把修正后回放的结果作为新的独立测试成绩。

## 复用与限制

- 专业器类缺少馆藏明示时，梅瓶/葫芦瓶仍使用已冻结的 v10 视觉支持索引缩小推理范围。明确的馆藏身份绕过该粗筛；图片变动、图库不一致或索引不完整时回退到直接看图。粗筛仍可能漏收，不能声称全库召回已知。
- 主体区域由 GrabCut 估计，分割可能不完整；颜色边界尤其是青绿、粉红和棕红之间仍可能漏收或误收。
- 原来的 v14 独立反例问题会误伤部分真葫芦瓶，因此只在缺乏明确器类时使用，不能替代主体一致性检查。
- 馆藏记录也可能含错误、分类差异或混合材质。结果按当前馆藏语义和照片共同决定，不能算成纯视觉识别提升。
- 双腹/三节是显式的外观细分；带盖、顶饰与腹部之间仍可能存在计数歧义。泛称葫芦瓶不再强制等同双腹。
- 本轮逐图检查由助手完成，属于 AI 辅助案例诊断，不是独立人工金标准或全库准确率。已见失败后的修正会单独记录，不能当作新测试成绩。

## 运行与验证

```bash
PYTHONPATH=src .venv/bin/python scripts/verify_catalogue_v15.py
PYTHONPATH=src .venv/bin/pytest -q
.venv/bin/ruff check src tests scripts
npm run build --prefix web
bash scripts/run_local.sh
```

完整扫描与中英文复用结果保存在 `artifacts/catalogue_visual_v15/verification/`；服务从 `artifacts/catalogue_visual_v15/jobs/` 读取相同结果。`verification.json` 汇总最终检查，`review.jsonl` 记录实际看图案例与局限。新缓存身份包含元数据、图像时间戳、判定代码、模型身份、颜色模型和粗筛索引哈希，避免修改馆藏类别后复用旧判定。

接口：`POST /api/search/set/jobs`，JSON `{"query":"梅瓶","method":"catalogue_visual"}`；随后 GET `/api/search/set/jobs/{job_id}?decisions=true` 取完整结果。旧 `joint_vlm` 方法及同步历史接口保留，历史接口的调用合同不变。页面“筛选匹配集合”的默认方法改为新路径，每件入选藏品详情展示本次判定依据。
